围绕问题空间收敛业务边界、统一语言与核心演进决策，严禁在本技能内输出数据库表结构、HTTP 路由或代码实现细节，必须把问题空间隔离在战略层以避免技术选型污染领域语义。

## 执行流程

1. 切分子域并锁定核心域：
   - 全新项目基于行业先验推演业务全貌；增量需求先读取现有 `context.md` 与 `context-map.md` 评估影响范围。
   - 识别决定核心壁垒的子域并围绕其发起讨论；将支撑域与通用域打包为单行行业默认摘要供用户一并确认。
2. 对齐统一语言与核心流水线：
   - 遇到术语含糊、一词多义或分水岭决策时，必须先读取并按 [grilling](../grilling/SKILL.md) 协议向用户发起前沿追问。
   - 沿时间轴拉出核心 `Command -> Workflow -> DomainEvent` 主干链条，收敛状态锁定、并发竞争与失败补偿等业务分叉规则。
3. 划定限界上下文与落盘文件：
   - 遵循无共享架构原则，依据同一概念在不同阶段的语义分裂点切分自治的限界上下文，并定义上下游协作模式如 `OHS`、`PL`、`ACL` 或 `SK`。
   - 新项目先在根目录落盘单一 `context.md`；当出现明显概念成簇或一词多义时，拆分为根目录 `context-map.md` 与各上下文目录内的 `context.md`。

## 上下文模板

根目录或上下文目录 `<module_path>/context.md`：

```markdown
# <上下文名称>

<1-2 句话说明职责定位与默认支撑策略>

## 术语

**<术语名称>**: <1-2 句话定义它是什么，而非做什么>
- 等价：`<CodeIdentifier>`
- 避免：<易混词 1>, <易混词 2>

## Workflow

- `<WorkflowName>`: `<Command>` -> `<DomainEvent>`
```

根目录 `context-map.md`：

```markdown
# 上下文地图

## 限界上下文

- [<上下文名称>](./<module_path>/context.md) — <职责与子域分类>

## 关系模式

- <上游上下文> [<角色标记>] -> <下游上下文> [<角色标记>]
  - 事件：发布 `<DomainEvent>`，下游订阅触发 `<WorkflowName>`
  - 同步端口：调用 `<PortTrait>` 完成即时校验或预占
```

## 架构决策记录规范

- 记录门槛：当决策同时满足难逆转、脱离背景令人费解、存在真实方案权衡三项条件时必须落盘 ADR；缺任一项即跳过以防低质文档泛滥。
- 存放与编号：全局决策存于根目录 `docs/adr/NNNN-slug.md`，上下文局部决策存于 `<module_path>/docs/adr/NNNN-slug.md`；尚未合入主干前可调整，一旦合入主干即永久锁定编号，当旧决策失效时通过新 ADR 声明替代关系，严禁重排已合入历史提交的编号，因为提交历史与切片说明已永久引用旧号。

```markdown
# <决策简短标题>

<1-3 句话说明背景、最终决定与核心原因>

## 备选方案

<仅当被否决方案值得保留教训时填写，否则省略本节>

## 影响

<仅当存在非显而易见的架构后果时填写，否则省略本节>
```
