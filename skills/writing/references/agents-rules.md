# AI 规则与 Skill 编写规范

面向 AI 的文档（`SYSTEM.md`、`AGENTS.md`、`SKILL.md` 及附属参考文件）本质上都是可执行的行为约束。常驻规则每轮消耗上下文与注意力，按需加载的 Skill 依赖精准的上下文指针唤醒，核心目标是最小化 Token 负载并最大化执行稳定性。

## 筛选与上下文预算

- 动笔前逐行执行 No-op 检验：如果删掉这一行，模型是否会犯下无法自行纠正的错误；若模型默认已会遵守，或信息可通过文件树、配置文件、`--help` 输出自行推导，直接删除整句并清理无实质约束的空洞修饰词。
- 遇到具体问题时抽象为通用原则，用稳定的行为约束覆盖整类场景，以适应工具演进与环境变化，避免硬编码单次症状、字面数字或易变工具参数。
- `SYSTEM.md` 只声明跨项目通用的协作身份、沟通风格、工具编排原则与高风险操作的人工确认红线。
- `AGENTS.md` 控制在 100 行以内，只保留非默认的构建与测试命令、静态分析无法捕获的隐含业务约束，以及指向深层文档的路径映射；目录结构、模块概览与通用常识留给模型自主检索，因为静态概览会干扰检索并推高推理开销。

## Skill 结构与渐进式拆分

遵循 Agent Skills 开放标准的三级渐进式披露机制（启动仅加载 `name` 与 `description`，命中后加载 `SKILL.md` 正文，执行中按需读取 `references/` 或调用 `scripts/`）：

- Frontmatter 默认只保留 `name` 与 `description` 两个字段，`name` 与技能目录名严格一致。
- 所有触发条件收拢在 `description` 中：前置核心先导词并按互斥使用场景做到一分支一触发（剔除同义重复）。模型自动触发的 Skill 仅在存在误触或高频相近场景时补充排除边界；仅人工显式调用的 Skill 设 `disable-model-invocation: true`，`description` 只保留单行人类摘要。
- `SKILL.md` 正文控制在 300 行以内，省去重复的技能名称一级标题与触发说明，直接从核心任务与执行流程开始；`references/` 下的独立参考文档保留一级标题以承载完整规范。
- 单一职责 Skill 直接在 `SKILL.md` 内写清流程与输出模板；多模式 Skill 将 `SKILL.md` 作为纯分发入口，把分支规范与模板拆入 `references/`，并规定每次仅单跳读取命中的那一个参考文件，防止无关分支干扰注意力。
- 保持单向依赖与单跳引用：`references/` 严禁反向引用主文件的阶段编号或编排指令，只使用稳定的能力或产物名称；调用已注册的常驻 Skill 时直接点名 `<name> Skill`，不写跨目录相对路径链接。
- 重复执行的确定性逻辑封装入 `scripts/` 并在正文中指示调用；无需读入上下文的静态资源放入 `assets/` 按路径引用；固定输出格式用代码块配 `<占位符>`，并将省略或触发条件就近写在占位符内，避免与正文重复。

## 引用标准与字面量边界

大模型在预训练阶段已经充分掌握了公认的工业标准、经典框架与方法论。直接点名这些标准，能用极少 Token 调出整套规范，远比用白话逐条解释精准。

- 当规则对应公认无歧义的标准或方法论时，如 BCP 14、SemVer、Conventional Commits、C4 模型、Unix 哲学、第一性原理、奥卡姆剃刀，直接写出名称作为基线，随后只补充需要收紧或调整的局部细节。
- 当需要大幅裁剪某个公认标准的核心环节时，跳过标准名称，直接正面列出需要保留的要素，防止模型受完整标准惯性影响，在长对话中把本想去掉的环节带出来。
- 当规则属于代码库私有的特殊约定或自定义工具链时，模型本身不了解这些规则，必须显式写清。
- 严格区分反引号字面量边界：仅文件路径、代码标识符、命令及精确配置状态字面量加反引号；架构模式、方法论与通用缩写（如 ADR、SSOT、DDD）不加反引号。

## 结构、句式与情态词

规则使用纯文本与 Markdown 列表符，每条独立规则单独成行，省去面向人类扫读的加粗、斜体与装饰性表格，防止长段落分散注意力。

- 有先后因果的执行步骤必须使用编号有序列表并明确可核查的完成判据以防抢跑；互斥分支拆分为独立的 `当 <触发条件> 时，<动作指令>` 条目，不将多分支用分号挤进同一句。条件前置能让自回归生成的动作词在预填充阶段即受因果掩码约束，防止未满足条件就先执行动作。
- 针对工程策略与工具配合，补充背后的原因或预期收益，写成 `<动作指令>，因为 <工程原因>` 或 `<动作指令>，以 <预期收益>`，帮助模型在未列举的边缘场景中按意图自主判断。
- 情态词遵循 BCP 14 规范，在中文规则中统一映射为必须、严禁、应当、优先、避免五个强度梯度，默认使用正向动作指令，因为模型对否定词不够敏感，只写否定句反而会提醒模型注意被禁止的对象。
- 必须与严禁只在拦截不可逆安全风险、或矫正极易触发的常见坏习惯时使用（如滥用 `grep` 与 `cat`）；每条严禁紧跟唯一合法的正向出口，写成 `严禁 <旧习惯>，必须使用 <新方案>`，存在唯一例外时补充 `仅当 <条件> 时改用 <备选路径>`；同一模块内相互独立的硬性约束控制在 3 条以内，防止过多强约束互相冲突。
- 当涉及工程权衡、工具选型或存在合理例外时，主要使用优先与应当，直接写明首选路径，为模型保留根据实际情况灵活调整的空间；避免仅用于温和提醒已知的低效做法，且紧跟推荐做法。
