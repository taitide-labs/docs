# 契约设计

遵循 Schema-First 与 SSOT 原则，在编写持久化或切片实现代码前锁定南北向对外协议与东西向跨上下文契约边界。

## 执行流程

1. 推导南北向入口契约：读取 `context.md`（存量变更同步核查既有 `contracts/` 与导出契约），拆出对外读写入口清单：
   - 当交付服务端 HTTP 接口时，默认按 OpenAPI 规划路由、入参约束与响应结构，业务拒止与校验失败统一遵循 RFC 9457 错误响应结构，由后续代码类型自动导出 `contracts/openapi.json` 并派生客户端 SDK；仅当涉及跨进程高频二进制通信或流式 RPC 时改用 Protobuf（以 `.proto` 为唯一事实源并记录 ADR）；当对外投递 Webhook 或跨独立系统事件流时遵循 CloudEvents 信封规范。
   - 当交付不包含服务端接口的独立命令行工具时，遵循 clig.dev 规范冻结子命令层级、参数类型、退出码与标准错误流契约。
   - 当演进存量接口时，遵守 Parallel Change 向后兼容原则：请求新增字段设为可选或提供默认值，响应仅增量添加字段，废弃字段标注弃用标记并保留过渡期输出。
2. 划定东西向跨界契约：对照 `context-map.md` 收敛全局 `contracts` 边界：
   - 严禁跨上下文直接导入对方的内部领域模型或切片模块，必须将跨界协作收敛至全局 `contracts` 模块，以切断上下文间的源码耦合。
   - 需要即时返回值驱动主控制流的调用定义为同步 `Port` 接口；单向通知与最终一致性联动定义为可扩展的开放枚举 `IntegrationEvent`（强制下游订阅方保留未知变体兜底分支），配合 Transactional Outbox 在本地短事务内落盘事件表后再经事件总线广播。
   - 将全局时钟、随机数等非确定性基础设施抽象一并收敛于 `contracts` 模块，以保证领域层与自动化测试的完全确定性。
3. 配齐写端并发防线与成对补偿签名：
   - 为每个写入口明确 Idempotency 幂等键来源，以及基于聚合版本号或 ETag 的 Optimistic Concurrency Control 冲突判定规则。
   - 严禁在持有活跃数据库事务期间调用跨上下文同步 `Port`，必须按“事务外同步预占 -> 开启本地短事务落库 -> 失败逆向释放”编排写流程，并为所有预占或扣减类同步 `Port` 成对定义幂等释放方法，以免长事务耗尽连接池或本地回滚造成跨界状态悬挂。
4. 对齐确认与回填坐标：
   - 向用户呈现结构化契约摘要（避免新建手写接口说明文档或手写 OpenAPI 文件，保持代码契约类型或 `.proto` 作为唯一事实源）。
   - 当涉及多限界上下文协作时，将敲定的同步 `Port`（含补偿方法）与 `IntegrationEvent` 名称回填至 `context-map.md`，按需落盘契约 ADR 或 `.proto` 文件并提交用户确认。
