# 契约设计

遵循契约优先原则，在书写任何持久化或切片实现代码前锁定跨端协议与跨上下文边界。

## 南北向对外契约

- Rust 后端服务端接口优先采用代码类型作为单一事实源，直接在契约入参和出参结构体上派生 `utoipa::ToSchema` 与 `#[utoipa::path]`，由集成测试命令导出 `contracts/openapi.json` 生成客户端绑定，避免双份 YAML 与结构体手写漂移。
- 当独立命令行工具不包含服务端接口时，遵循 `clig.dev` 规范在命令行入口模块冻结子命令层级、参数类型、退出码与标准错误流契约。
- 接口演进必须保持向后兼容：请求结构体新增字段使用 `Option<T>` 或 `#[serde(default)]`，响应结构体仅增量加字段，废弃字段保留输出并标注弃用标记。

## 东西向跨上下文契约

- 需要即时返回值驱动主控制流的跨上下文调用必须收敛至全局 `contracts` 包内的同步端口 trait，如库存预占或优惠券核销；严禁直接导入其他上下文的 `domain` 或 `slices` 内部模块。
- 单向通知与最终一致性联动统一使用带 `#[non_exhaustive]` 属性的 `IntegrationEvent` 枚举，写路径在本地短事务内写入 `outbox_events` 表后通过事件总线广播。
- 需要全局统一注入的时钟等非确定性基础设施抽象一并定义在 `contracts` 包中，以保证领域层与测试环境的完全确定性。

## 并发事务硬边界

- 当写切片编排流程既要调用外部同步端口又要修改本地数据库表时，必须先完成外部端口调用并取得凭证，再开启本地短事务落库；当本地事务失败时立即执行同步补偿释放外部凭证。
- 严禁在持有活跃数据库事务期间发起跨上下文异步端口调用，以免回滚导致跨边界状态泄露或在并发峰值下耗尽连接池触发死锁。
