# 客户端设计

基于已对齐的领域统一语言与接口契约构建客户端界面，通过真实运行与实操体验完成产品需求验证与多端交互基线锁定。

## 执行流程

1. 对齐规范与底座：
   - 当处理存量变更时，读取既有 `DESIGN.md`、`context.md` 与共享 `ui/` 组件库，优先复用既有语义令牌与受控组件。
   - 当启动全新客户端应用时，明确支持的目标平台家族集合（桌面与 Web、移动端、终端 TUI）与具象视觉参照物，在客户端根目录（单包项目在仓库根目录）落盘 `DESIGN.md`；关键页面布局存在分叉时可在同一路由挂载 2-3 个结构迥异的变体对比拍板后清理，随后建立亮暗对称的主题材质令牌、多端自适应 `ui/` 受控组件层、全状态展厅（Gallery）与静态守卫测试。
2. 编写界面与状态单测：
   - 按接口契约编写协议请求与 RFC 9457 错误解析代码，仅在底层网络传输或数据源层挂载覆盖正常流、空态、加载态、慢请求竞态与业务错误的确定性拦截桩，使连接真实后端时仅需切换环境配置而无需重写调用代码。
   - 组装本次需求涉及的目标页面（超大型全新客户端优先完成核心主干流页面闭环以确认需求，大量同质长尾子页面可留待后续按切片独立补齐），同步补齐 `store` 状态纯函数单元测试。
3. 宿主自验：
   - 启动本地宿主，使用浏览器、桌面或终端自动化工具走通业务流、切换亮暗双主题与各目标平台视口，结合无障碍树与视觉能力排查修复控制台报错、对齐偏移、外置焦点环裁切与横向溢出。
4. 用户确认：
   - 交由用户在真实运行环境中实操体验并确认需求，根据反馈调整界面；若体验暴露出业务术语歧义或接口字段缺失，回退至战略设计或契约设计修订。
5. 固化验收测试：
   - 用户拍板定稿后，补齐或增量更新基于无障碍语义选择器的无头交互验收测试，供本地与 CI 常态化执行；后续无界面变更时不触发视觉验证。

## 架构与测试细则

- 视觉与组件分层：严禁在业务页面直接编写裸色值、裸字号圆角或绕过共享 `ui/` 层手搓控件，必须仅组合 `ui/` 受控组件与布局原语（内边距归组件自身、间距归父容器、避免双倍内边距；缺少变体时先扩充 `ui/` 层再消费），并由静态守卫测试扫描拦截硬编码裸色值、内联样式覆盖及校验亮暗主题键值对称。
- 状态与即时响应归属：领域状态归 `store`（仅暴露只读访问与语义变更方法），瞬态表单草稿归页面，虚拟长列表复用行状态按稳定领域 ID 外置存储；需主线程即时响应的禁用或关闭拦截约束预先声明为状态属性，避免阻塞等待异步回调。
- 交互验收测试边界：注入传输拦截桩、内存存储与手动时钟零等待快进；严禁绑定内部节点层级或导出私有状态供测试读取，必须仅使用无障碍角色、标签或可见文本语义选择器定位元素，覆盖主流程、空态/加载/错误/断网、慢请求竞态不覆盖新结果、返回栈状态保留、长列表滚动复用与多端视口切换。

客户端根目录或仓库根目录 `DESIGN.md`：

```markdown

<1-2 句话写明支持的目标平台家族集合（桌面与 Web / 移动端 / 终端 TUI）、核心用户任务与具象视觉参照物，不使用空泛形容词>

## 设计原则

- <3-4 条可检验的层级、密度与克制度准则，如依靠字阶、分割线与表面深度建立层级而非色块填充>

## 色彩与表面材质

- 令牌事实源：<指向代码中的主题令牌与表面材质文件路径；下文仅引用语义令牌名，不抄写具体色值或像素>
- 色阶与强调色：<页面底色、卡片、内凹区、凸起区的明暗递进关系，以及单一主强调色与状态色的允许作用范围>
- 表面材质：<卡片、内凹槽、凸起控件与浮层在亮暗主题下的顶光高光、边框、阴影与毛玻璃成对规则>

## 排版、空间与多端适配

- 字体与排版：<标题、正文、等宽辅助标签的层级职责及中西文标点与字距规则>
- 空间与对齐：<容器尺度、间距语义关系、内边距归组件与间距归父容器约束、同心圆角及共享对齐脊线>
- 跨平台家族映射：<桌面指针紧凑密度与多栏常驻导航、移动端最小触控热区与导航栈/底部抽屉变形、终端整格字符对齐的适配规则>

- 命令与文案规范：<主按钮、菜单、快捷键多入口同源规则，上下文经济文案原则及二次弹窗省略号 `…` 约定>

## 动效清单

## Do's and Don'ts

- Don't: <明确禁止的廉价套路或越界做法>
```
