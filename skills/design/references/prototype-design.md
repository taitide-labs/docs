# 原型设计

在冻结重度后端实现前，按产品交付形态建立稳定的表面交互与行为基线，避免底层接口尚未收敛时反复返工界面结构或命令参数。

## 按应用形态分级执行

- 当交付图形客户端应用时，依序完成六步闭环：
  1. 锁定 Design Tokens：严禁在业务组件内散落硬编码色值或魔术尺寸，必须先统一定义语义颜色、间距比例、字体阶梯与亮暗双色主题变量，后续页面与组件仅引用语义令牌。
  2. 构建无状态基础组件层：实现纯受控展示与输入原语，内置完整键盘导航、焦点管理与无障碍语义角色，不掺杂任何网络或存储依赖。
  3. 编写解耦状态层：状态管理面向抽象客户端端口编程，原型期注入严格对齐阶段 2 契约模型的确定性桩实现，覆盖正常流转、空态、加载态与业务错误码反馈。
  4. 组装页面与沉淀 Feature Map：组装目标页面并在仓库维护统一的功能词汇地图，明确页面路由、核心交互区命名与状态机流转，确保人类审查者与后续并发代理使用一致的界面坐标指代元素。
  5. 编写无头行为测试：在脱离真实网络服务的前提下自动化验证核心交互流转、表单校验错误提示、状态转换与无障碍语义树。
  6. 真实渲染走查与 Golden Snapshot 基线：在真实渲染窗口逐条走通交互路径，保存亮色与暗色双主题下的 Golden Snapshot 视觉快照基线，供下游增量迭代与合龙阶段回归比对。
- 当交付独立命令行工具时，遵循 clig.dev 规范冻结正交的一级动作与二级对象子命令层次、帮助文案、非交互静默模式、退出码契约以及标准输出数据流与标准错误诊断流隔离冒烟测试；严禁将某个二级子命令专有的局部参数提升为全局顶层选项，必须将其限定在对应子命令作用域内。
- 当交付纯后端服务或无界面领域平台时，核对阶段 2 契约清单完备后显式记录跳过表面原型说明，经用户确认后进入阶段 4。
