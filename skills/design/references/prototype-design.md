# 原型设计

在冻结重度后端逻辑实现前，根据应用表面形态建立稳定的交互与行为基线，避免底层接口尚未收敛时反复返工界面结构或命令参数。

## 按应用形态分级执行

- 图形客户端应用：
  1. 锁定 `Design Tokens`：首先统一定义语义颜色、间距比例、字体阶梯与亮暗双色主题变量，严禁在业务组件内散落硬编码色值或魔术像素。
  2. 构建无状态基础组件层：实现纯受控展示与输入原语并内置无障碍语义角色与键盘焦点支持，不掺杂任何业务网络请求或持久化依赖。
  3. 编写解耦状态层：状态管理面向抽象客户端端口编程，原型期注入严格对齐阶段 2 接口模型的确定性桩实现，完整覆盖正常、空态、加载与业务错误码反馈。
  4. 组装页面与沉淀 `Feature Map`：组装目标页面并在仓库维护一份统一的功能词汇地图，明确页面路由、核心交互区命名与状态机流转，确保人类审查者与后续并发代理使用一致的界面坐标指代组件。
  5. 编写无头行为测试：在脱离真实网络服务的前提下自动化验证核心交互流转、表单校验错误提示、状态转换与无障碍语义树。
  6. 真实渲染走查与 `Golden Snapshot` 基线：在真实渲染窗口逐条走查交互路径，保存亮色与暗色双主题下的 `Golden Snapshot` 视觉快照基线，供下游增量迭代与合龙后实现零消耗回归比对。
- 命令行工具：遵循 `clig.dev` 规范冻结一级动作与二级对象正交子命令层次，严禁将只属于某个二级子命令的专有参数提升至一级全局选项；锁定帮助文案、非交互静默模式、退出码契约以及标准输出数据流与标准错误诊断流隔离冒烟测试。
- 纯后端微服务或无界面领域平台：在核对 `contracts` 与对外开放接口清单完备后，显式记录跳过表面原型说明并立即进入阶段 4。
