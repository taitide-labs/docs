# 命令行客户端设计

遵循 clig.dev 规范，基于已对齐的领域统一语言与接口契约构建命令行应用，通过真实终端实操确认交互体验并锁定命令契约。

## 执行流程

1. 对齐命令树：
   - 当处理存量变更时，读取既有命令入口与 `context.md`，遵循 Parallel Change 保持既有子命令、参数与退出码兼容。
   - 当启动全新应用时，遵循 clig.dev 规划正交子命令层次、参数约束、结构化输出（如 `--json`）与退出码语义。
2. 编写命令与解析单测：
   - 若为远程服务客户端，按接口契约编写请求与 RFC 9457 错误解析代码，在底层传输层挂载确定性拦截桩，使连接真实后端时仅需切换配置；纯本地工具对接内存或隔离临时目录桩（超大型工具先完成核心主干子命令）。
   - 同步补齐命令参数解析与纯逻辑单元测试。
3. 终端自验：
   - 在终端实际执行主干命令，核验 `--help` 引导、正常流、错误退出码、非交互管道模式与 `stdout` / `stderr` 流隔离。
4. 用户确认：
   - 交由用户在真实终端实操体验并确认交互，根据反馈调整命令结构或文案；若实操暴露出业务术语歧义或接口字段缺失，立即暂停扩展，经用户确认后回退至战略设计或契约设计修订。
5. 固化验收测试：
   - 用户拍板定稿后，补齐覆盖子命令路由、退出码、管道静默及 `stdout` 与 `stderr` 流隔离的命令行验收测试，供本地与 CI 常态化执行。

## 架构细则

- 参数作用域隔离：严禁将二级子命令专有的局部参数提升为全局顶层选项，必须限定在对应子命令作用域内。
- 可测命令入口：入口遵循 Parse, Don't Validate 将原始参数解析为受限命令，业务编排注入抽象端口、标准流与环境时钟依赖，避免写死全局进程状态。
