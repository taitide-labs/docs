# 战略设计

遵循 `Domain Modeling Made Functional`（`DMMF`）、`Big Picture Event Storming`、`Shared-Nothing` 与 `SSOT` 收敛业务边界与领域语义。严禁在本阶段输出数据库表结构、接口路由或具体代码实现，必须将讨论严格约束在业务问题空间，以避免技术细节过早污染领域模型。

## 执行流程

1. 切分子域并锁定核心域：
   - 当处理存量变更时，先读取既有 `context.md` 与 `context-map.md` 评估波及范围。
   - 围绕决定竞争壁垒的核心域发起前沿追问；将支撑域与通用域打包为单行行业默认方案摘要供用户默认采纳，仅在用户提出异议时展开调整，以将注意力集中于核心域分叉。
2. 对齐统一语言：
   - 围绕核心域提炼或修订业务术语，非英文术语绑定英文代码 `等价` 标识符以建立全仓 `SSOT`（术语本身即为英文时省略 `等价` 行），同时列明 `避免` 混用的近义旧词。
   - 当发现用户用词含糊、一词多义或与既有代码标识符冲突时，立即构造具体边缘场景检验概念边界；当修订存量术语时，同步核查绑定的代码标识符与下游契约是否受波及。
3. 梳理流水线与收敛 `Hotspots`：
   - 沿时间轴拉出核心 `Command -> Workflow -> DomainEvent` 主干链条，针对状态锁定、并发竞争与异步失败补偿识别 `Hotspots` 并逐轮收敛业务规则。
   - 当启动全新项目时，同步划定首期 `Walking Skeleton` 的最小端到端闭环范围。
4. 划定限界上下文与落盘产物：
   - 遵循 `Shared-Nothing` 原则，依据同一概念在不同业务阶段的语义分裂点切分自治的限界上下文，上下文协作角色限定于 `OHS`、`PL`、`ACL`、`CF`（跨上下文共享的受限基础值原语与交互契约统一归入 `PL` 与 `OHS`）。
   - 当概念或边界敲定后，立即创建或更新文档以防上下文遗失：全新项目先从根目录单一 `context.md` 起步；当出现一词多义或术语明显成簇时，拆分为根目录 `context-map.md` 与各上下文目录内的 `context.md`，并按需落盘战略 `ADR`。

## 产物模板

根目录 `context.md` 或上下文目录 `<module_path>/context.md`：

```markdown
# <上下文名称>

<1-2 句话说明该限界上下文定位及纳入的支撑域、通用域默认摘要>

## 术语

**<术语名称>**: <1-2 句话定义它是什么，而非做什么>
- 等价：<CodeIdentifier；当术语本身即为英文时省略本行>
- 避免：<易混词 1>, <易混词 2>

## Workflow

- `<WorkflowName>`: `<Command>` -> `<DomainEvent>`
```

根目录 `context-map.md`：

```markdown
# 上下文地图

## 限界上下文

- [<上下文名称>](./<module_path>/context.md) — <职责与子域分类>

## 关系模式

- <上游上下文> [<上游角色，如 OHS, PL>] -> <下游上下文> [<下游角色，如 ACL, CF>]
  - 事件：发布 `<DomainEvent>`，下游订阅触发 `<WorkflowName>`
  - 同步端口：调用 `<PortName>` 完成即时校验、预占或查询
```
