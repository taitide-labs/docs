# 任务拆解与工单编排

遵循 Inverse Conway Maneuver 与 SSOT 原则，基于已合入主干的冻结基线，在 GitHub 上通过层级工单与阻塞依赖图隔离并发实现代理的读写作用域。

工单正文只描述业务目标、规则边界与代码库真值坐标，将工作树操作、格式化与门禁命令留给 `implement` Skill 与自动化流水线，以保持工单高信噪比。

## 执行流程

1. 核对前置基线：确认本次交付涉及的冻结基线（迁移脚本、共享领域、切片入口或客户端底座及带 `wip` 跳过标记的黑盒验收测试）已合入主干。
2. 创建工单拓扑：
   - 当交付只涉及单个独立切片时，直接创建 1 个垂直切片工单，按需关联目标版本的 GitHub Milestone。
   - 当涉及多切片协同或跨端交付时，创建或复用目标版本的 GitHub Milestone，先创建 1 个 Parent Issue 概括整体业务闭环，再挂载各并行切片 Sub-issue 与 1 个末尾合龙验收 Sub-issue：
     - 全新项目将首条最小端到端通路显式标为前置 Walking Skeleton，并令其余并行切片 Blocked by 该工单。
     - 末尾合龙验收工单统一 Blocked by 全部并行切片工单，形成可供人工或调度面板按序派发的有向无环图。

## 产物模板

Parent Issue:

```markdown
# <需求交付名称>

<1-3 句话概括本次交付覆盖的业务链路与整体完成定义>

## 上下文与契约

- 领域上下文：<context-map.md 与相关 context.md 路径>
- 契约与交互基线：<contracts/、DESIGN.md 或数据库迁移目录坐标>
```

垂直切片工单（独立 Issue 或 Sub-issue）：

```markdown
# <业务动作与领域对象名称>

<1-3 句话描述业务规则与异常拒止边界>

## 指向坐标

- 接口与交互契约：<contracts/、DESIGN.md 或切片入参出参契约路径>
- 共享基线：<数据库迁移脚本、共享 domain 或 ui/ 底座路径；不涉及时省略>
- 切片目录：<切片、命令模块或页面所在目标目录>

## 验收场景

- <待激活或需补齐的验收测试路径 :: scenario_fn_1>
- <待激活或需补齐的验收测试路径 :: scenario_fn_2>
```

末尾整体验收 Sub-issue：

```markdown
# <Parent Issue 名称> 端到端整体验收

<1-2 句话说明激活跨上下文集成旅程测试、切换客户端真实服务连接（如有）及契约一致性校验的合龙目标>

## 验收与合龙坐标

- 端到端旅程测试：<端到端旅程测试目录或文件路径；不涉及时省略>
- 契约与客户端：<contracts/openapi.json 与客户端连接配置路径；不涉及时省略>
```
