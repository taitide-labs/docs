# 任务拆解与工单编排

遵循 `Inverse Conway Maneuver` 与 `SSOT` 原则，基于已合入主干的冻结契约与黑盒验收测试基线，在 GitHub 上通过层级工单与阻塞依赖图反向隔离并发实现代理的读写作用域。

工单正文只描述业务目标、规则边界与代码库真值坐标，将工作树操作、格式化与门禁命令留给 `implement` Skill 与自动化流水线，以保持工单信噪比最大化。

## 编排规则

1. 核对本次设计涉及的迁移脚本、领域模型、切片入口骨架及带 `wip` 跳过标记的黑盒验收测试已合入主干。
2. 当交付只涉及单个独立切片时，直接创建 1 个垂直切片工单，按需关联对应版本的 GitHub `Milestone`。
3. 当涉及多切片协同或跨前后端交付时，创建或复用目标版本的 GitHub `Milestone`，先创建 1 个 `Parent Issue` 概括整体业务与架构闭环，再创建各并行切片 `Sub-issue` 与 1 个末尾合龙验收 `Sub-issue` 并挂载至 `Parent Issue` 下：全新项目将首条最小端到端通路显式标为前置 `Walking Skeleton` 并令其余并行切片 `Blocked by` 该工单；末尾合龙工单统一 `Blocked by` 全部并行切片工单，形成可供人工或调度面板按序派发的有向无环图。

## 工单模板

`Parent Issue`：

```markdown
# <需求交付名称>

<1-3 句话概括本次交付覆盖的业务链路与整体完成定义>

## 上下文与契约

- 领域上下文：<context-map.md 与相关 context.md 路径>
- 契约基线：<contracts/ 与数据库迁移目录坐标>
```

垂直切片工单（独立 `Issue` 或 `Sub-issue`）：

```markdown
# <业务动作与领域对象名称>

<1-3 句话描述业务规则与异常拒止边界>

## 指向坐标

- 接口与端口契约：<contracts/、Feature Map 或切片入参出参契约路径>
- 迁移与共享领域：<数据库迁移脚本与共享 domain 相关类型路径>
- 切片目录：<切片或页面所在目标目录>

## 验收场景

- <待激活测试文件 :: scenario_fn_1>
- <待激活测试文件 :: scenario_fn_2>
```

末尾整体验收 `Sub-issue`：

```markdown
# <Parent Issue 名称> 端到端整体验收

<1-3 句话说明激活跨上下文集成旅程测试、切换客户端真实 SDK、导出 OpenAPI 契约与合龙验证目标>

## 验收与合龙坐标

- 端到端旅程测试：<端到端旅程测试目录或文件路径>
- 契约与客户端：<contracts/openapi.json 与客户端适配器目录>
```
