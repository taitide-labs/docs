从宏观到微观逐层推进软件设计并冻结前置基线。按阶段顺序推进；进入下一阶段前必须先完成当前阶段产物校验或确认，严禁跨阶段跳跃以免契约未稳先写实现。

## 阶段调度

每次只加载当前所处阶段的指南，避免后续实现细节提前污染当前上下文；当任意阶段面临多方案权衡需要用户拍板时，必须先读取 [grilling](../grilling/SKILL.md) 后再展示前沿问题：

1. 战略设计与决策记录：读取并执行 [domain-modeling](../domain-modeling/SKILL.md)，收敛核心域、统一语言、上下文地图与战略决策文档。
2. 契约设计：读取 [contract-design.md](references/contract-design.md)，冻结南北向接口模型、跨上下文同步端口与异步事件契约。
3. 原型与交互基线：读取 [prototype-design.md](references/prototype-design.md)，按产品形态锁定图形界面、命令行契约，纯后端服务记录跳过说明后直通下一阶段。
4. 战术设计与黑盒验收冻结：读取 [tactical-design.md](references/tactical-design.md)，搭建工作区基础设施、数据库迁移、共享纯领域核、切片契约骨架与可编译的带标记黑盒验收测试。
5. 任务拆解与工单编排：读取 [task-slicing.md](references/task-slicing.md)，在主干恒绿基线上按垂直切片创建原生 GitHub 里程碑、父工单与并发子工单。
6. 示范或并行交付：进入实现阶段时，读取并执行 [implement](../implement/SKILL.md) 在独立工作树交付垂直切片并合入主干。

## 增量变更路由

当在既有工程仓库执行增量需求时，依据影响面裁剪入口阶段：

- 仅在现有切片内修改局部计算或界面样式时，直接进入阶段 4 补充增量验收场景后再拆分工单。
- 需要跨切片联动或修改字段与事件契约时，从阶段 2 起步。
- 涉及新增业务边界或重塑核心术语时，从阶段 1 起步。
