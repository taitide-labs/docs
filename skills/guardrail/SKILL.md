遵循信任倒金字塔原则配置确定性防线：优先用编译期类型与静态扫描拦截问题，其次用自动化状态机与黑盒验收验证行为，仅当静态检查与自动化测试均无法识别语义意图时才补充极简的自然语言规则。

## 选型优先级

1. 类型系统与新类型包装：当缺陷源于非法值状态、精度丢失或状态机非法流转时，必须在 `primitives` 或共享 `domain` 层封锁私有字段构造与状态签名，让错误写法在编译期直接报错。
2. 编译器与黑名单规则：当问题表现为禁止使用的标准库阻塞调用、隐式吞错宏或特定代码坏味道时，优先通过 `Cargo.toml` 编译器规则与 `clippy.toml` 禁用清单强制阻断，而非在 `AGENTS.md` 追加文字提醒。
3. 结构抽象语法树规则：当规则涉及同一 Crate 内的跨切片互引、读路径违规引用写侧领域模型、纯计算模块引入异步运行库或模块内联测试时，在 `rules/*.yml` 编写 `ast-grep` 规则。
4. 自然语言兜底：当问题完全依赖语义判断（如禁止无意义复述注释或为临时补丁辩解）且前 3 层无法机械判别时，才提炼为 1 条条件前置、正向指令清晰的 `AGENTS.md` 条目。

## 执行流程

1. 根因归类：定位引发误用的根本机制，避免只针对单次表面报错写脆弱匹配。
2. 正向提示落盘：严禁编写含糊的否定警告，每条新增静态规则与报错文案必须同时给出错误原因和唯一合法替代方案，并在正反两个最小探针样本上验证触发行为。
3. 全仓清扫验证：规则入库后立即运行 `mise run check` 对存量代码全量清扫；存在历史债务时在同一 PR 内一次性迁移至新规范，确保规则落地即主干全绿。
