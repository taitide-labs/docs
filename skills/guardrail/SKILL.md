遵循信任倒金字塔原则实施代码库园艺：优先用受限类型系统与静态分析在编译前消除错误空间，其次用状态机属性与变异验证守住运行时行为，仅当静态分析与自动化测试均无法机械判别语义意图时才补充极简自然语言规则。

## 选型优先级

1. 类型系统与新类型包装：依照 `Making Illegal States Unrepresentable` 原则，当缺陷源于非法值状态、精度丢失或状态机非法流转时，必须在 `primitives` 或共享 `domain` 层封锁私有字段构造与状态签名，使错误写法在编译期直接报错。
2. 编译器开关与黑名单规则：当问题表现为禁止使用的阻塞调用、裸浮点运算、隐式吞错或 `mod.rs` 组织坏味道时，优先通过 `Cargo.toml` 的 `[workspace.lints]` 下划线开关与 `clippy.toml` 的连字符禁用清单强制阻断，而非在 `AGENTS.md` 追加文字提醒。
3. 结构抽象语法树规则：当规则涉及同一包内的跨切片互引、读路径违规引用写侧领域模型、纯计算模块引入异步运行库或叶子源码内联测试时，在 `rules/*.yml` 编写三毫秒级 `ast-grep` 规则，并与懂类型推导的 `Clippy` 互补配对。
4. 自然语言兜底：当问题完全依赖纯语义判断（如抑制为临时补丁辩解的无意义注释）且前三层无法机械判别时，才按照条件前置与单一事实源准则提炼为一条极简 `AGENTS.md` 规则。

## 执行流程

1. 根因归类：定位触发误用的深层机制，避免仅针对单次表面语法写脆弱补丁。
2. 报错文案即即时提示词：严禁编写含糊的否定警告或复读编译器前缀主语；每条新增规则的 `reason` 或 `message` 字段必须以硬性指令直接写明具体工程危害与唯一合法正向替代方案，并在正反两个最小探针样本上实测触发行为。
3. 全仓清扫验证：规则入库后立即执行 `mise run check` 对存量代码全量清扫；若存在历史遗留债务，必须在同一 PR 内一次性完成迁移，确保规则落地即主干全绿。
